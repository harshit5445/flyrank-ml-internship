Refresh / Content Opportunity Scoring

A machine-learning ranking approach for identifying content pages that deserve review based on search and analytics signals.

Lane 2 Machine Learning Content Opportunity Scoring FlyRank ML Internship

Author: Harshit

Repository: GitHub repository

0. Abstract

This project asks whether February 2026 search and analytics signals can support a ranked queue of content pages for refresh review. The analysis uses a time-separated feature window from February 2026 and evaluates a March 2026 outcome proxy based on measured Google Search Console clicks. A client-grouped Random Forest is compared with a transparent baseline using Precision@50 on the same held-out records. On the held-out set, the Random Forest achieved Precision@50 of 0.980 compared with 0.380 for the baseline, with a ROC-AUC of 0.846. The resulting ranking is intended as decision support for content and SEO reviewers rather than as a causal prescription that a refresh will recover traffic.

1. Introduction / Problem Statement

Content teams may have many pages that could potentially benefit from review, but manual review of every page is expensive. The goal of this project is to turn available search and analytics signals into a ranked review queue.

The decision is therefore: which content records should a reviewer inspect first?

The unit of analysis is one content/page record. The model uses information available during February 2026 and evaluates an outcome observed during March 2026.

Important framing: The model identifies records that resemble pages associated with the evaluated outcome. It does not establish that refreshing a page will cause traffic to recover.

Why use ML?

A fixed rule can capture one obvious signal, such as low CTR for a given position. ML allows multiple signals to be combined into a single ranking and then evaluated against a transparent baseline on held-out data.

Outcome proxy

The March outcome proxy is went_dark, constructed from measured March Google Search Console clicks and measured GSC days. Records with measured March GSC data and zero clicks are treated as positive outcome records.

Data safety

Client and content identifiers are used only for grouping, joining, and evaluation. They are not used as predictive features.

Future March outcome fields are excluded from the February feature matrix to prevent leakage.

No client names, client-identifying domains or URLs, private queries, credentials, or raw private exports are included in the public paper.

3. Methodology

Time-separated setup

February 2026 is used as the feature window and March 2026 is used as the outcome window. This prevents the model from using future outcome information when constructing its features.

Model

The model is a Random Forest classifier with the following configuration:

  • n_estimators: 300
  • max_depth: 8
  • min_samples_leaf: 20
  • class_weight: balanced
  • random_state: 42

Client-grouped split

Records are split by client so that the same client does not appear in both training and test sets.

105,652 Training records
55,887 Test records
0 Client overlap

Evaluation metric

The primary ranking metric is Precision@50. This measures how many of the first 50 ranked records are positive outcome records.

5. Limitations & Honest Framing

  • The March outcome is a proxy and does not directly measure whether a content refresh would succeed.
  • The model identifies patterns associated with the evaluated outcome; it does not establish causal relationships.
  • Search and analytics availability varies across records, so missingness and measurement availability are part of the data context.
  • Feature importance describes model behavior rather than proving that a feature causes the outcome.
  • A high Precision@50 on this held-out sample does not guarantee the same performance on every future dataset.
  • The ranked output is intended to prioritize human review, not automatically trigger content changes.

6. Interpretation

The Random Forest substantially concentrated positive outcome records near the top of the held-out ranking compared with the transparent baseline.

The strongest model reliance was on February impressions, clicks, and CTR. This indicates that the model primarily used search visibility and engagement signals when constructing its ranking.

The model's false positive in the top 50 is also important: ranking systems are not perfect classifiers, so the output should be reviewed by a human rather than treated as an automatic decision.

7. Recommendation

Use the ranking to review high-scoring pages first, inspect their February search and analytics context, validate the page manually, record the human decision, and monitor any future intervention.

Recommended workflow: Model ranking → human page review → content decision → future monitoring.

The output is decision support, not a causal prescription.
